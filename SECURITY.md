# Security Policy

## Supported versions

AROP is currently pre-release. Security fixes are applied to the latest development line. A supported-version matrix will be published with the first public release.

## Reporting a vulnerability

Do not open a public issue for a suspected vulnerability.

When the GitHub repository is created, GitHub Private Vulnerability Reporting will be the preferred channel. A monitored security contact will also be published here before public contribution is enabled. Until then, report privately to the repository owner through an already established trusted channel.

Include, when possible:

- affected protocol or SDK version;
- affected component and deployment mode;
- reproduction steps or a minimal fixture;
- security impact and required preconditions;
- suggested remediation or embargo constraints.

Do not include live credentials, customer data, reusable Run Tokens, cookies, or private endpoints. Use synthetic evidence.

## Response targets

The public project will publish named responders before v0.1. The intended process is acknowledgement, triage, coordinated remediation, release, and disclosure. Exact service-level targets remain a publication configuration until maintainers and the security contact are named.
